The `fixtures/` directory holds the small data files the test suite consumes.
None of these are committed by default — every fixture is either user-generated
(per the recipes below) or sourced from a third-party corpus the project can't
redistribute (LibriSpeech).

Each test that needs a fixture calls `XCTSkip(...)` when the fixture is missing,
so the suite passes even on a clean checkout. The fixtures are required only to
gate the actual parity / accuracy claims; the cardinality / API-shape tests
(`ChunkSizeTests`, `LanguageTests`, `NormalizationTests`, `CohereTests`,
`ParakeetTests`) run unconditionally.

## File list

| File                       | Required by                          | Committed? | Generated by         |
| -------------------------- | ------------------------------------ | ---------- | -------------------- |
| `sample.wav`               | `MelParityTests`, `BackendIntegrationTests` | Yes (allowed by `.gitignore`) | User (recipe below)  |
| `mel_reference.bin`        | `MelParityTests`                     | No (regenerate per checkout) | Python recipe below  |
| `vocab.txt` or `vocab.json` | `TokenizerTests`                     | Yes (`vocab.*` allowed by `.gitignore`) | Python recipe below  |
| real `.aimodel` assets     | `BackendIntegrationTests`            | No (gitignored, external) | `convert/<model>/` (see below) |
| LibriSpeech (external)     | `ParityTests`                        | No — `LIBRISPEECH_PATH` env var | User downloads upstream |

The end-to-end backend tests (`BackendIntegrationTests`) don't read from
`fixtures/`; they load the real palette4 assets from a directory you point at via
the `VOIXFUL_TEST_MODELS_DIR` env var (see "Real `.aimodel` assets" below).

## `sample.wav` — 5-second 16 kHz mono PCM Float32

The mel parity test needs a short audio clip to feed through both NeMo's
preprocessor and `MelExtractor`. Any clean speech sample works; we recommend
a 5-second clip to keep the reference blob under ~1 MB.

Constraints:

- 16 kHz sample rate (no resampling — NeMo's preprocessor assumes 16 kHz).
- Mono (single channel).
- 32-bit float PCM (so the reference path doesn't introduce quantization
  noise of its own).
- 5 seconds (80,000 samples). Shorter is fine; longer wastes test time.

How to make one:

```bash
# Option A: record yourself reading a sentence into the system mic.
ffmpeg -f avfoundation -i ":0" -t 5 -ac 1 -ar 16000 -sample_fmt flt \
       -c:a pcm_f32le fixtures/sample.wav

# Option B: pull any LibriSpeech utterance and convert it.
ffmpeg -i some-librispeech-utt.flac -t 5 -ac 1 -ar 16000 -sample_fmt flt \
       -c:a pcm_f32le fixtures/sample.wav
```

Commit `sample.wav` to the repo — `.gitignore`'s `!fixtures/*.wav` rule allows it.

## `mel_reference.bin` — NeMo preprocessor output for `sample.wav`

A flat little-endian float32 blob containing NeMo's
`AudioToMelSpectrogramPreprocessor` output for `sample.wav`, shape `[128, T]`
row-major (mel bins are the slow axis; time is the fast axis). The test loader
in `MelParityTests.loadFloat32Blob(at:)` is shape-agnostic; it asserts that the
total element count matches what `MelExtractor.extract(samples:)` produces.

How to make one (requires the NeMo conversion environment from
`convert/pyproject.toml`):

```python
import numpy as np
import soundfile as sf
import torch
import nemo.collections.asr as nemo_asr

# Load the published checkpoint (downloads ~600 MB the first time).
m = nemo_asr.models.ASRModel.from_pretrained("nvidia/nemotron-speech-streaming-en-0.6b")
prep = m.preprocessor

# Read sample.wav as a torch float32 tensor.
audio, sr = sf.read("fixtures/sample.wav", dtype="float32")
assert sr == 16000, f"sample.wav must be 16 kHz, got {sr}"
assert audio.ndim == 1, "sample.wav must be mono"
audio_t = torch.from_numpy(audio).unsqueeze(0)            # [1, N]
length = torch.tensor([audio_t.shape[1]], dtype=torch.int64)

# Run the preprocessor. NeMo returns [B, n_mels, T].
with torch.inference_mode():
    mel, _ = prep(input_signal=audio_t, length=length)
mel_np = mel.squeeze(0).cpu().numpy().astype(np.float32)  # [128, T]

# Write as flat little-endian float32. The test loader is shape-agnostic.
with open("fixtures/mel_reference.bin", "wb") as f:
    f.write(mel_np.tobytes(order="C"))
print(f"wrote fixtures/mel_reference.bin shape={mel_np.shape} dtype=float32")
```

Do NOT commit `mel_reference.bin` — regenerate per checkout. Reasoning: the
reference depends on a specific NeMo / PyTorch version pair and can drift
silently if committed. Keeping it out of git means the test fixes itself on a
fresh `pip install`.

## `vocab.txt` or `vocab.json` — SentencePiece vocab dump

The tokenizer tests need a plain-text vocabulary file (one piece per line, line
number = id) to exercise the round-trip. The published Nemotron checkpoint ships
a SentencePiece binary `tokenizer.model`; the recipe below dumps it to the
plain-text form the loader expects.

```python
import sentencepiece as spm
import nemo.collections.asr as nemo_asr

m = nemo_asr.models.ASRModel.from_pretrained("nvidia/nemotron-speech-streaming-en-0.6b")

# Find the SentencePiece model path used by the tokenizer. NeMo wraps it
# behind .tokenizer.tokenizer.model_file or similar — VERIFY in Phase 1.
sp_model_path = m.tokenizer.tokenizer.model_file
sp = spm.SentencePieceProcessor(model_file=sp_model_path)

with open("fixtures/vocab.txt", "w", encoding="utf-8") as f:
    for i in range(sp.get_piece_size()):
        f.write(sp.id_to_piece(i) + "\n")
print(f"wrote fixtures/vocab.txt with {sp.get_piece_size()} pieces")
```

The plain-text form is the best-effort vocab `TokenizerTests` parses. Commit
`vocab.txt` — `.gitignore`'s `!fixtures/vocab.*` rule allows it (it's small; the
English Nemotron vocab is 1024 pieces).

## Real `.aimodel` assets — for `BackendIntegrationTests`

The end-to-end backend tests load the real converted assets, produced per model
by the convert pipelines (`convert/nemotron-streaming/`, `convert/parakeet-tdt/`,
`convert/cohere-transcribe/`). Each asset is a **self-contained** `.aimodel`
directory — `main.mlirb` + `main.hash` + `metadata.json` plus a bundled
`pieces.txt` (no loose sibling vocab file).

These are large and gitignored, so they are **not** committed and **not** read
from `fixtures/`. Point the tests at a directory holding the palette4 assets via
the `VOIXFUL_TEST_MODELS_DIR` env var:

```bash
VOIXFUL_TEST_MODELS_DIR=~/repos/voixful-models swift test --filter BackendIntegration
```

The directory should contain `nemotron-speech-streaming-en-0.6b-palette4.aimodel`,
`parakeet-tdt-0.6b-v3-palette4.aimodel`, and
`cohere-transcribe-03-2026-palette4.aimodel`. Without the env var the tests
`XCTSkip`.

## LibriSpeech — external, not committed

`ParityTests` consumes LibriSpeech test-clean for the WER gate. The corpus is
not redistributable in this repo. Point at it via the `LIBRISPEECH_PATH`
environment variable:

```bash
export LIBRISPEECH_PATH=/Volumes/data/LibriSpeech/test-clean
swift test --filter ParityTests
```

The test expects either:

1. A flat directory layout: `${LIBRISPEECH_PATH}/<utterance_id>.flac` (or `.wav`)
   plus `${LIBRISPEECH_PATH}/transcripts.txt` with `<utterance_id>\t<reference>`
   lines.
2. The canonical LibriSpeech nested layout: `${LIBRISPEECH_PATH}/<speaker>/<chapter>/<utterance>.flac`.
   In this case still provide `transcripts.txt` at the root — the recursive
   walk finds the audio.

To generate `transcripts.txt` from a stock LibriSpeech download:

```bash
cd $LIBRISPEECH_PATH
find . -name "*.trans.txt" -exec cat {} \; | \
    awk '{printf "%s\t", $1; for (i=2; i<=NF; i++) printf "%s%s", $i, (i==NF?"\n":" "); }' \
    > transcripts.txt
```

Each `.trans.txt` line in LibriSpeech is `<utt_id> <space-separated reference>`;
the awk one-liner converts the first space to a tab and leaves the rest alone.
